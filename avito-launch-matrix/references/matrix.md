# Контракт матрицы

Различать направление (услуга), ЦА (покупатель), Job (событие и прогресс), связку (заголовок+оффер+обложка), размещение (связка+город+волна) и файл фото. Последние два не подтверждают публикацию.

Использовать стабильные ID D01/J01/B01-01/P0001/H-B01-01/S02 либо сохранять существующие пользовательские коды вроде 1.1. Проверять код вместе с заголовком, не назначать фото только по позиции строки.

Пример: 7 направлений × 3 связки = 21 самостоятельный заголовок и 21 оффер. Это пример, не обязательная структура. N размещений считать как сумму явных распределений; не добирать число выдуманными услугами.

## Справочник связок

`bundle_id, направление, ЦА, Job/ситуация, заголовок, оффер, CTA, вопрос квалификации, доказательство, E-ID/источник, статус основания, приоритет, ограничение, hero_asset_id, текст обложки, описание обложки`.

Углы: конкретный результат; причина смены/барьер; прозрачность состава/процесса. Не считать синонимы разными Jobs. Каждому заголовку дать свой оффер. Если заказан полный текст объявления, добавить отдельный столбец полного текста.

## Основная таблица размещений

`placement_id, волна, город, геогруппа, direction_id, bundle_id, ЦА, триггер, заголовок, оффер, CTA, доказательство, плюс гипотезы, риск, приоритет, новое/обновить/резерв, статус, действующий ID/URL, основание города, Фото1..N, Файл1..N, ImageNames, ImageUrls, комментарий`.

При статистике добавить показатели и расчёты с единицами/периодом. Пропуски не заполнять нулями. Не менять фактические статусы. При исходном шаблоне сохранять его архитектуру, данные и формулы. Не создавать десятки листов без отдельной задачи.

## Каталог фото

`asset_id, позиция, bundle_id/область применения, заголовок, текст кадра, краткое описание/роль, точное имя файла, ссылка просмотра, исходное фото, фактический размер/соотношение, статус`.

Не писать «остальные фото из папки»: дать упорядоченные имена. Если существует только описание, не выдумывать URL. Ссылки Google Drive держать в «Фото N — просмотр», не ImageUrls. Для архива: ZIP без вложенных папок, точные ImageNames в нужном порядке, ImageUrls пусто. Правила и лимиты фида проверять при сборке. Не считать папку публичной по факту загрузки.

## Приёмка

Проверить D/V/N/G, самостоятельность и наличие всех связок, уникальность ID, совпадение кода/заголовка/оффера, города/волны, повторения услуг для проверки допустимости. Проверить каждую назначенную фотографию: наличие, порядок, отсутствие повторов внутри галереи и наличие в архиве. Проверить соответствие обещаний между обложкой, оффером и услугой. Сравнить исходные ячейки/формулы до и после дополнения и визуально проверить изменённые области по навыку таблиц. Указать пробелы и блокеры, не объявлять матрицу валидированным фидом без сборки по схеме площадки.
